# PHASE 1 — 전체 URL·기능 전수 조사 보고 (2026-11-05)

기준: 브랜치 `fix/v3.2-integrity-regressions`. 화면별 상세 표(URL, 줄 수, API 존재/누락, 버튼, 로딩·오류·빈 화면, 반응형, 영문 문구, 의심 패턴)는 자동 생성 [`phase1/INVENTORY.md`](phase1/INVENTORY.md), 원자료는 `phase1/inventory.json`, 생성기는 `tests/audit/phase1_inventory.mjs`(재실행 가능).

## 1. 조사 방법

1. 세 앱의 라우터에서 URL → 화면 파일을 추출.
2. 각 화면과 공통 셸(App.vue, components)의 모든 API 호출을 추출해, **해당 화면 역할의 실제 토큰**(구매자/관리자(2FA 통과)/승인 판매자)으로 개발 시드 게이트웨이에 실제 요청. 경로가 어떤 라우터에도 없으면 `ROUTE_NOT_FOUND`로 판정(메서드 추정이 틀린 경우 모든 메서드로 재시도해 오탐 제거).
3. 정적 점검: 핸들러 없는 버튼, `href="#"`, 로딩·오류·빈 상태 처리, 반응형 클래스, 영문 문구, 하드코딩 색상, 접근성 속성, 가짜 수치·보장 문구 패턴.
4. 의심 패턴은 사람이 원문을 읽어 판정(무해한 기본값과 가짜 표시 구분).

한계: 버튼의 "실제 동작"은 핸들러 유무와 API 존재까지만 자동 확인. 브라우저 클릭 E2E와 화면 폭별 렌더링은 PHASE 4~6 교체 시 수행(NOT_RUN).
