- 작업일: 2026-11-25 / 브랜치: `work-order/phase6` (미커밋, 6-0 위에 적층)
- 결정: 결정-19 (공통 "무료배송" 문구 금지, 판매자 선택값 그대로 표시)

## 1. 무엇을 바꿨나

| 지시 | 구현 |
|---|---|
| 1. 등록·수정 필수 | 단건 등록·수정·일괄 등록·URL 발행 API에서 배송정책 필수(`SHIPPING_POLICY_REQUIRED` 400, 위조 id는 기존 `INVALID_SHIPPING_POLICY`). 정책 0개 판매자에게는 "먼저 등록" 안내 문구. "공급처 가져오기"는 서버 생성 경로가 없어(전수 확인) 해당 없음 |
| 2. 기본 정책 | 서버·선택 UI는 이미 존재(`is_default` + 부분 유니크). 3개 등록 화면에서 기본값을 미리 선택만 하고 자동 연결은 하지 않음. 카탈로그 상세의 기본값 폴백 표시는 제거 |
| 3. 코드 기본값 제거 | `orders.js`의 `?? 3000`·`?? 30000`, `LEGACY` 요금 분기, 클라이언트 `DEFAULT_*` 전부 제거. 정책 없거나 비활성 정책 상품은 주문·인용 모두 `SHIPPING_POLICY_REQUIRED` 409 (아무것도 저장하지 않음) |
| 4. 기존 64개 | DB 직접 수정 없음. 판매자 미지정 목록(`shipping=unassigned`) + `bulk-update` 일괄 지정, 관리자 목록 필터 + 검수 대기열 `shipping_missing` 표시. 심사 승인·판매 전환도 정책 없이 불가 |
| 5. 표시 일원화 | 서버 `shippingText()` 하나가 문구 생성. 상세·목록·스토어·인용 응답에 `shipping_text` 포함, 클라이언트는 그대로 표시. 무료→"무료배송", 유료→"배송비 N원", 조건부→"N원 이상 구매 시 무료 (미만 M원)", 수량별→"N개당 M원", 도서산간 정책 추가비 suffix |
| 6. 구조화 데이터 | `productGraph`에 `OfferShippingDetails` 추가. 무료 0원, 유료·조건부·수량별은 기본 배송비. 값 없으면 생략 |
