- 작업일: 2026-11-25 / 브랜치: `work-order/phase6` (미커밋, 6-6 위에 적층)

## 1. 무엇을 바꿨나

| 지시 | 구현 |
|---|---|
| 1. 키 파일 API화 | `GET /<key>.txt`: `INDEXNOW_KEY`와 바이트 일치 때만 키 본문 그대로 200(text/plain, 개행 없음). 키 없음·오명·형식 외는 404. 정적 키 파일은 두지 않음. 정확한 `.txt`(`/llms-full.txt` 등)가 정규식보다 먼저 처리됨 |
| 1. 루트 워커 경로 | `CRAWL_PATHS`+`run_worker_first`에 `/*.txt` 추가(플랫폼 glob, `*` 심층 일치). apex는 키를 몰라도 됨 — 전부 API로 전달 |
| 2. 큐 적재 지점 | `notifyProductChanged(env, id, before)` 신설: 작성 후 색인 가능(ACTIVE+APPROVED)이거나 방금 색인 집합을 떠났을 때만 적재(삭제 신호 포함). 연결 9곳 — 파트너 전체수정·가격 2종·재고·식별정보·일괄변경(판매중지 포함), 관리자 상태·심사결정, M2C 흥정 수락. 등록 3경로는 전부 DRAFT 생성이라 적재하지 않고 승인 시점이 진입점. 상품 쓰기 우선이라 큐 실패는 `console.warn`만 |
| 2. 엔드포인트 | 현행 `https://api.indexnow.org/indexnow` 유지 + `INDEXNOW_ENDPOINT` 재정의 유지(아래 근거). drain의 200·202 성공 판정은 네이버 응답표와도 일치 |
| 3. 소유 확인 meta | apex `/`가 ASSETS HTML에 `naver-site-verification`·`google-site-verification` 삽입 — env 코드가 있을 때만, 값 이스케이프, 코드 없으면 바이트 동일 통과. `/`를 `run_worker_first`에 추가(`RUN_WORKER_FIRST`로 A01 핀) |
| 3. DNS TXT | 소유 확인을 DNS TXT로 하면 두 코드를 등록하지 않는다(보고서·wrangler 주석·`HUMAN_CHECKLIST.md` §5-6) |

## 2. 엔드포인트 근거 (공식 문서 확인, 2026-11-25)

- [indexnow.org](https://www.indexnow.org/): "support from Microsoft Bing, Naver, Seznam.cz, Yandex, Yep" — **네이버 참여 확인**, Google은 불참.
- [indexnow.org/documentation](https://www.indexnow.org/documentation): 키 규칙 8~128자 `[A-Za-z0-9-]`(키 파일 라우트 정규식에 반영), 한 번 제출하면 참여 엔진 전체에 전파 → 글로벌 엔드포인트 하나로 충분.
- [네이버 서치어드바이저 IndexNow 가이드](https://searchadvisor.naver.com/guide/indexnow-request): `GET/POST https://searchadvisor.naver.com/indexnow`, 본문 `{host, key, keyLocation, urlList}`(현행 drain 페이로드와 동일), 성공 200·202·실패 400·403·422·429·500, POST당 최대 10,000 URL(현행 배치 100 유지).
- 결론: 제출 대상은 글로벌 엔드포인트 1곳 유지. 네이버·빙 개별 전송 불필요. 실제 제출은 운영자 작업(`HUMAN_CHECKLIST.md` §5-4·§5-6).
