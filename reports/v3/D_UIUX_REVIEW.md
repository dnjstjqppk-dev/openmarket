# D. UI/UX 검토 보고서

검증 환경: 로컬 `wrangler dev`(workerd + D1) + Vite 3종, Chrome headless(CDP) — PC 1440×900, 태블릿 820×1180, 모바일 390×844. 스크린샷 29장: `reports/v3/screenshots/`.

## 1. 기존 화면 평가 (수정 전)

가장 큰 문제는 시각 디자인이 아니라 **화면이 사실과 다른 내용을 표시**한다는 점이었습니다. 고객 신뢰와 표시·광고 관련 법적 위험이 직접 걸린 문제라 디자인 개선보다 우선 처리했습니다.

| 분류 | 발견 내용 |
|---|---|
| 허위 사업자 정보 | 푸터의 법인명·대표·사업자번호·통신판매업 번호·에스크로 가입 배지 하드코딩 |
| 조작된 수치 | "24시간 1,420개 판매", "28명 보는 중", 5시간마다 리셋되는 마감 타이머, 가짜 배송 단계와 항공편 번호 |
| 시스템과 다른 약속 | 90일 무조건 무료반품, 1.5만원 이하 무회수 즉시환불, 100% 정시배송, 10만원 쿠폰팩, 미연동 결제수단(카카오페이·Stripe·PayPal) 노출 |
| 잘못된 입력 기본값 | 체크아웃에 가짜 수령인·주소·통관부호, 가입 약관 동의 기본 체크 |
| 금액 불일치 | 체크아웃 합계에 서버가 청구하지 않는 관세 가산, 쿠폰 계산식 상이 |
| 동작 불가 | 관리자 로그인 후 진입 불가, 정산 화면 항상 빈 화면, 로그인 실패 시 가짜 세션 생성 |
| 반응형 | 모바일 390px에서 스토어 헤더·판매자 배송관리 가로 넘침 |
| 완성도 | 영문·국문 혼용, 다국어 키 누락으로 버튼에 `addToCart` 노출 |

## 2. 변경한 화면

| 앱 | 화면 | 변경 |
|---|---|---|
| 구매자 | 로그인 · 회원가입 | 실제 인증만, 세션 만료 안내, 명시적 개별 동의, 비밀번호 정책 실시간 표시, 접근성 label/role |
| 구매자 | 체크아웃 (재설계) | 서버 견적 기반 금액, 판매자별 배송비, 결제수단을 실제 설정대로 표기(시뮬레이터/테스트키/비활성), 구매조건 확인 동의(전자상거래법 제8조), 멱등키로 중복 주문 방지 |
| 구매자 | 결제 결과 (신규) | PG 복귀 → 서버 승인, 시뮬레이터 승인 화면 |
| 구매자 | 주문 상세 (재설계) | 판매자(배송 단위)별 카드와 상태별 액션: 판매자별 취소, 반품·교환 신청, 구매확정, 환불 내역 표시 |
| 구매자 | 헤더·푸터·홈·상품상세 | API 기반 사업자 정보, 직영/입점 판매주체 고지, 실측 판매지표만, 실제 캠페인 종료시각 기반 타이머, 모바일 헤더 간소화(하단 탭바 활용) |
| 구매자 | 약관·환불 안내 | 시스템 동작과 일치하는 문구 + "법률 검토 전 초안" 표시 |
| 판매자 | 로그인·세션 | 실제 계정 로그인, 만료 처리, 가짜 폴백 제거 |
| 관리자 | 로그인·내비게이션 | 운영자 계정 로그인, 가드 일원화 |
| 관리자 | **운영 사업자·법인 전환** (신규) | 사업자 등록(DRAFT) → 검토 확인 → 전환, 미결 채무 대시보드 |
| 관리자 | **공급사·발주** (신규) | 발주서 상태 전이, 소싱 연결(공급가·마진·권한 근거) |
| 관리자 | **데이터 대사·지급** (신규) | 18개 검증, 판매자 지급·이체 기록, 사업자별 시산표 |
| 관리자 | 상품 관리 | 심사 승인/반려 |

## 4. 남은 UI 과제 (정직한 범위 표기)

지시서는 필요 시 전체 디자인 교체를 요구하지만, 이번 작업에서는 **거래·신뢰·법적 표시에 직접 걸린 화면을 우선** 재설계했고 나머지는 기능·사실 정합성만 맞췄습니다.

- 전체 화면 디자인 시스템 통일(색·타이포·간격 토큰)과 영문/국문 문구 일원화: 미착수.
- 관리자 상단 메뉴 14개가 PC에서 두 줄로 줄바꿈 — 사이드바 구조로 전환 권장.
- 홈 배너 문구("최대 85% 파격 할인")는 DB 데이터 — 실제 프로모션으로 교체 필요(O03).
- 판매자 배송관리는 화면에서 송장 입력이 가능하나, 브라우저 E2E는 판매자 세션 토큰으로 API를 호출해 출고 처리를 검증했습니다(입력 폼 자동화는 미작성).
- 접근성: 새로 만든 화면은 label·role·aria-live를 적용했으나 기존 화면 전체 접근성 점검(명도 대비, 키보드 포커스)은 미실시.
