# F. 상용화 판정 보고서

## 판정: **NO-GO** (실거래 개시 불가)

코드의 거래 무결성·보안은 이번 작업으로 검증 가능한 수준에 올라왔지만, **실제 돈을 받을 수단(PG 계약), 판매 주체(사업자 등록), 실제 상품·판매자 데이터**가 없어 실거래를 시작할 수 없습니다. 이 셋은 코드가 아니라 사업 준비 사항이며, 시스템은 이 상태에서 주문·결제를 받지 않도록 **의도적으로 차단(fail-closed)** 되어 있습니다.

### 판정 근거

| 게이트 | 상태 | 근거 |
|---|---|---|
| 인증·권한 우회 0건 | **충족** (알려진 범위) | 익스플로잇 0/18, 보안 스위트 S01~S22 |
| 중복 결제 0건 | **충족** (테스트 범위) | I03·I04·I21·I22 |
| 정산 불일치 0건 | **충족** (테스트 범위) | 대사 18개 검사, 모든 시나리오 후 통과 (I31, E2E 26, 브라우저 B11) |
| 데이터 손실 0건 | 부분 | 불변 원장·트리거 구현 / 운영 백업·복구 리허설 미실시 |
| 실 결제 수단 | **미충족** | PG 계약·키 없음 (O01) |
| 판매 주체 | **미충족** | 사업자등록·통신판매업 신고·운영자 등록 없음 (O02) |
| 실제 상품·판매자 | **미충족** | 데모 데이터 (O03, `evidence/07`) |
| 운영 DB 반영 | **미충족** | `d1_20`~`d1_25` 미적용 (O04, 승인 필요) |
| 법적 문서 | 미충족 | 약관·개인정보처리방침·환불규정은 초안 |

"1바이트의 오차도 없음"은 위 테스트와 대사가 다루는 범위에서만 확인된 것이며, 부하·장애 주입·실 PG 환경 검증은 아직 하지 않았습니다.

## CONDITIONAL GO 로 가기 위한 조건 (권장 순서)

| # | 조건 | 담당 | 시스템 측 준비 |
|---|---|---|---|
| 1 | 사업자등록 + 통신판매업 신고 → 관리자 `운영 사업자`에서 등록·활성화 | 대표님 | 완료 |
| 2 | PG(예: 토스페이먼츠) 계약 + 구매안전서비스(에스크로) 가입 → `PAYMENT_MODE=live`, 키 등록 | 대표님·PG사 | 완료 (테스트 키로 먼저 검증) |
| 3 | 운영 D1 백업 → `d1_20`→…→`d1_25` 순서 적용 → 대사 확인 (B 보고서 6·7절) | 개발 (승인 필요) | 절차 준비 완료 |
| 4 | Worker Secret 설정: `JWT_SECRET`, `ALLOWED_ORIGINS`, `CARRIER_WEBHOOK_SECRET`, `ALERT_WEBHOOK_URL`(대사 실패 알림), `TOTP_ENCRYPTION_KEY`(2단계 인증 비밀키 암호화, 미설정 시 JWT_SECRET에서 파생 — JWT_SECRET 교체 시 2단계 인증 재등록 필요), 선택: `ADMIN_IP_ALLOWLIST` | 개발 | 미설정 시 503 / 알림은 `NO_CHANNEL` 기록 |
| 5 | 데모 데이터 제거, 실제 상품·이미지(권리 확보)·판매자 등록 | 대표님·MD | 점검 SQL 제공 |
| 6 | 첫 운영자 계정 생성: `scripts/create-admin-sql.mjs`로 SQL 생성 → 검토 후 적용(승인 필요) → 첫 로그인 때 2단계 인증 등록 → 콘솔에서 역할별 운영자 추가 | 개발·대표님 | 스크립트·화면 준비 완료 |
| 7 | 약관·개인정보처리방침·환불규정 법률 검토 확정 | 법무 | 초안 표시 중 |
| 8 | 이메일 발송사 연동 (비밀번호 재설정) | 개발 | O06 |

1~8을 마치면 **"직영 상품 + 소수 검증 판매자, 국내 배송, 카드결제 한정"** 범위의 CONDITIONAL GO를 검토할 수 있습니다. 택배 조회 연동(O07), 세금계산서(O09)는 그 범위 확대 전 조건입니다. 판매자 입점 신청(O05)과 관리자 2단계 인증·권한 분리(O11)는 V3.1에서 구현했습니다. 개인정보 파기·접속기록(O10)은 V3.1에서 코드로 구현했고, 보존기간·적립금 소멸·후기 존치 정책의 법률 검토가 남았습니다.

## 법률·계약 검토 필요 사항 (개발자가 확정하지 않음)

- 전자상거래법: 사업자 정보 표시, 청약철회 기간(현재 7일 설정, 연장은 정책 결정), 3영업일 내 환급, 통신판매중개자 고지 문구, 구매안전서비스 의무.
- 표시·광고: 할인율·판매량·후기 등 표시 근거 (현재 실측값만 표시하도록 수정함).
- 개인정보 보호법: 수집 항목·보유기간·파기, 처리방침, 국외 이전(Cloudflare), 영업양도 시 이전 통지.
- (V3.1) 탈퇴 정책: 주문 기록 5년·문의 3년 보존 후 파기(env로 조정), 잔여 적립금 소멸(동의 필수, `CREDIT_FORFEITURE_INCOME` 계정 — 세무 처리 확인), 후기·문의 본문 존치(작성자명만 '탈퇴회원') — 약관·처리방침에 반영 필요. 접속기록은 자동 삭제하지 않음(보관기간 정책 결정 필요).
- (V3.1) 롤링 리저브: 판매자별 비율(0~50%)·보류일(1~365일)은 입점 계약서에 명시 필요.
- (V3.1) 반품 배송비: 사유별 귀책(단순변심·사이즈=고객, 불량·파손·오배송·설명상이=판매자), 무료배송 주문 전체 반품 시 왕복 차감, 판매자의 귀책 변경(근거 필수) — 전자상거래법 제18조 기준으로 약관·상품페이지 고지 문구 확정 필요.
- (V3.1) 입점 심사: 수집 서류(사업자등록증·통신판매업신고증·통장사본, 신분증 미수집)와 보관기간, 판매자 이용약관(현재 초안 표시) 확정 필요.
- 판매자 입점 계약: 수수료(bps), 정산 주기, 정산 후 환불 차감·이월, 롤링 리저브.
- 공급사 계약: 재판매·이미지 사용 권한 근거(시스템에 근거 입력 필수로 구현).
- 세무: 부가세, 세금계산서·현금영수증, 판매자 정산 증빙, 개인→법인 전환 시 처리.

## 이번 작업의 범위와 미완료 고지

- 지시서의 "전체 UI/UX 재설계"는 거래·신뢰·법적 표시와 관련된 화면만 재설계했습니다(D 보고서 4절).
- 부하·성능 시험, 운영 환경 백업 복원 리허설은 하지 않았습니다.
- 운영 배포, 운영 DB 변경, 실결제, 운영 시크릿 변경은 **하지 않았습니다**. 변경 사항은 커밋되지 않은 작업 트리 상태입니다.

## V3.1 후속 작업 (2026-11-05)

판정은 **NO-GO 유지**입니다. 출시 차단 항목(O01~O04)은 모두 사업·운영 승인 사항이라 이번 작업으로 바뀌지 않았습니다.
코드로 해결 가능한 항목 중 O05·O10·O11·O14·O18·O19를 해소했고, 작업 중 추가 결함 9건(N01~N09, P1 4건)을 발견해 수정했습니다(A 보고서 3-1b). 보안·무결성 스위트 75/75, 기능 E2E 26/26, 익스플로잇 0/18.
실브라우저 E2E는 이번에 다시 돌리지 않았습니다 — 변경·신규 화면(입점 신청·현황, 입점 심사, 계정 보안, 관리자 로그인 OTP, 반품·교환, 주문상세 수량취소·반품 사유, 대사, 정산, 마이페이지 탈퇴)은 타입 검사와 빌드만 확인했습니다.
남은 코드 항목: O12(API 속도 제한 — Cloudflare WAF 권장), O13(나머지 화면 재설계), O15(특가 가격 엔진), O16(Go 코드 처리 결정), O17(부하 시험).
